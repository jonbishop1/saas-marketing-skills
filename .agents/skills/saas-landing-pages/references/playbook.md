# Page blueprints

## Developer evaluation page

Task and supported environment → input/output example → smallest runnable path → integration and failure boundaries → evidence → pricing or usage model → next action.

## Data evaluation page

Workload and result → source-to-destination diagram → supported behavior → reconciliation evidence → permissions and operating requirements → scoped evaluation → commercial next step.

## Section specification

For each section record: question answered / role / content / proof source / visual / action / mobile treatment.

## Review example

If a page says “Start now” but the product requires a platform administrator and approved warehouse credentials, replace the ambiguous promise with a sample path and a clear real-data evaluation path. Measure which path produces meaningful value, not merely which button gets more clicks.
