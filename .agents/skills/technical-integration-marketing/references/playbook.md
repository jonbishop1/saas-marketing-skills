# Integration brief

Shared task / audience / interface type / supported versions / authentication and permissions / data flow / expected result / limits / cost / maintenance owner / support boundary / evidence / next action.

## Fictional examples

A replay CLI inside CI should document what triggers capture, how secrets are excluded, what artifacts are stored, and how a developer reproduces a failure. A data connector should document update and delete semantics, schema behavior, and who handles partial failures.

## Partnership language

“Example using the public API” and “official partner integration” make different claims. Use the latter only when the relationship and asset permissions are established. Preparing a draft listing does not authorize submission.

## Maintenance gate

Assign an owner to interface/version changes and broken examples. If the team cannot support a proposed integration, publish only the accurately scoped example or defer the page.
