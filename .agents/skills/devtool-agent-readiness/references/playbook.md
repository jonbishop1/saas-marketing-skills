# Task-scoped rubric

| Dimension | Evidence question |
| --- | --- |
| Discovery | Can the evaluator find the canonical task path and supported interface? |
| Understanding | Are prerequisites, version, inputs, outputs, limits, and cost clear? |
| Authorization | Is there a documented, appropriately scoped authentication path? |
| Execution | Can the authorized evaluator perform the defined task? |
| Verification | Can it distinguish a correct result from a superficial success? |
| Recovery | Are errors, retries, partial results, and cleanup actionable? |

Each row needs status / source or trace / limitation / proposed fix. Keep documented and hands-on results separate. Avoid a single league-table score unless the weighting, missing-data handling, and sensitivity are disclosed.

## Fictional public-only finding

“The API docs describe scoped authentication and an example request. We did not obtain credentials or execute the task. Discovery and documented setup are assessable; execution and recovery remain unknown.” This supports a documentation finding, not “agent ready.”

## Report privacy

Named brands can illustrate publicly documented practices. For audience aggregates remove names, domains, unique configurations, quotes, and small identifiable cells; do not assume replacing a company name is sufficient anonymization. Exclude records where permission or confidentiality is uncertain.
