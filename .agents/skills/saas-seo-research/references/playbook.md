# Opportunity table

Query / task / audience / evidence source / observed result types / demand estimate or unknown / product fit / canonical asset / useful next step / priority rationale.

## Fictional examples

“HTTP status codes” is broad education. “Replay a sanitized webhook locally in [supported framework]” is a task closer to a request-replay product. Prioritize only after inspecting the results and verifying the product path.

“What is a data warehouse” is broad education. “Reconcile late-arriving updates from [source] into [warehouse]” can support a practical evaluation if the product handles that behavior. Do not imply it does when support is unverified.

## Research limits

A single result set is a snapshot with location and personalization limits. Third-party volumes are estimates. If tools are unavailable, deliver a hypothesis backlog and an explicit verification plan rather than pretending to have completed live keyword research.
