# Claim ledger

Claim / type / intended decision / evidence / conditions / counterevidence / permission / publication wording / status.

## Benchmark protocol

Task / baseline and configuration / product configuration / version / workload / correctness check / measurement method / repeated-run plan / resource and cost accounting / exclusions / failure reporting.

## Fictional correction

Replace “10× faster for all pipelines” with a measured, scoped result only if a reproducible test supports it. If no test exists, write “Designed for [specific task]” only when product behavior supports that description, and propose the test separately.

## Customer case gate

Record permission, baseline, intervention, observation window, attribution limits, and approved quotes. An anonymized scenario must not imply a real customer or measured outcome. Do not publish identifying configurations or small private cohorts.
