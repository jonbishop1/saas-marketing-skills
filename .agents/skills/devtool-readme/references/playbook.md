# README outline

1. Product name and concrete task.
2. Input → output example; screenshot or diagram if it teaches something.
3. Prerequisites and smallest verified command sequence.
4. Expected result and common recovery path.
5. When it fits, limitations, compatibility, and operating boundary.
6. Docs, examples, support, security reporting, license, and contributing.

## Example decision

A fictional request replay README should show a sanitized request and the replay result, not only badges and a list of features. If a command requires a paid hosted account, say so before the command. A connector README should state whether the example mutates a destination and how to clean it up.

## Review questions

Can an unfamiliar developer identify the task, supported environment, cost or credential prerequisite, expected output, and next step without opening five unrelated links? Which answer was actually verified?
